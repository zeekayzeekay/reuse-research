# Validation and evidence boundaries

The current release is **v0.6.1**, an advisory research workflow. The executable helpers are unchanged from the v0.6.0 package used in the closing pilots; v0.6.1 clarified that every card-bearing candidate needs a selection reason, including documented candidates outside the briefed/queued set.

## Reproducible offline checks

```bash
python -m unittest discover -s tests -p "test_reuse*.py" -v
```

The 84 checks use synthetic fixtures and temporary directories. They exercise bounded retrieval, query coverage, source ownership/excerpts/hashes, evidence bindings, role-balanced review, whole-solution preservation, selection visibility, case inventories, cache provenance, timing states and unfinished handoffs. They do not need GitHub authentication, network access or candidate installations.

Packaging validation and successful skill installation establish discoverability and file integrity. They do not establish reliable automatic invocation or recommendation quality across agents. Earlier Codex invocation checks selected the skill for substantial features and skipped cosmetic/bypass requests; native Claude invocation verification remains pending.

Two fresh requests withheld expected repository identities and prior conclusions. A separate editing request combined historical captures with actual ordinary-keyword baseline packets and ten primary README captures; it tested retention and interpretation with no new retrieval credit.

All 13 protected alternatives remained briefed and visible with primary sources, assessments and next checks. The editing report retained Timeline Studio and Palmier alongside OpenChatCut, Diffusion Studio and video-use. It compared whole bases with components and transferred source-derived stale-proposal, asset-lifecycle, FPS, rotation, scene-reset and recovery cases into proposed checks.

Both fresh agents received deadline reminders; the research-workspace agent also received an accounting reminder based on the editing failure. Its final accounting was therefore assisted. No desired repository names or architectures were supplied.

A bounded spot check reviewed ten unique consequential evidence cards and relevant captured source context. Parent recomputation matched the final evidence/case/accounting artifacts. These checks do not constitute complete independent verification of every finding.

On a saved pool of 411 candidates and 70 captures, three local briefing/ranking repetitions had median runtimes of 0.168 seconds without whole-solution protection and 0.192 seconds with five protected alternatives. This excludes network requests, agent judgments and source reading; it is not end-to-end performance evidence.

## What remains unqualified

Discovery is incomplete, and absence from captured results does not prove no suitable project exists. Earlier extractor and agent-hub pilots also missed independently suitable references. These results do not establish an equal-budget retrieval advantage or comprehensive GitHub recall.

Source inspection and unrun tests reveal designs and intended behavior, not successful execution. Candidate runtime, integration, maintenance responsiveness and adoption eligibility need project-specific checks. A passed accounting audit certifies recorded visibility/provenance, not semantic relevance or production fitness.

The time presets are approximate targets. The observed overruns remain timing failures. Automatic invocation is host-dependent and is not a mandatory enforced gate.

Raw pilot captures, local project context and development history are retained outside the published repository. The offline suite is reproducible from this checkout; the pilot table is a summary of observed local runs, not a fully bundled replication dataset.
